# 中英文固件构建与资源、驱动分布

本文说明 `labplus_Ledong_v2` 与 `mpython_v3` 中英文固件如何选择，以及界面资源和驱动代码分别放在哪里。当前语言由构建参数决定，**不是设备运行时切换**。

## 构建中文或英文固件

在 WSL 中进入仓库的 `port/` 目录，并激活 ESP-IDF 5.4.3：

```bash
source ~/.espressif/tools/activate_idf_v5.4.3.sh
cd /mnt/g/labplus-project/labplus_mpython_esp32s3/port
```

中文是默认语言。四种板卡/语言组合各使用独立构建目录：

```bash
idf.py -B build_ledong_v2_zh -D MICROPY_BOARD=labplus_Ledong_v2 -D MICROPY_LANGUAGE=zh build
idf.py -B build_ledong_v2_en -D MICROPY_BOARD=labplus_Ledong_v2 -D MICROPY_LANGUAGE=en build
idf.py -B build_mpython_v3_zh -D MICROPY_BOARD=mpython_v3 -D MICROPY_LANGUAGE=zh build
idf.py -B build_mpython_v3_en -D MICROPY_BOARD=mpython_v3 -D MICROPY_LANGUAGE=en build
```

项目自定义的 `merge_bin` 已加入默认构建目标，所以一次 `idf.py ... build` 会在应用构建完成后打包 LittleFS，并生成完整 `.bin` 和 `.uf2`（板卡支持 UF2 时）。输出位于对应的构建目录，文件名包含板卡、版本、提交、日期和语言标记。只重新打包时，从 `port/` 目录运行，例如：

```bash
ninja -C build_ledong_v2_en merge_bin
ninja -C build_mpython_v3_en merge_bin
```

`idf.py merge-bin` 是 ESP-IDF 自带的合并操作，只生成 IDF 的 `merged-binary.bin`；它不执行本项目的 LittleFS 资源打包。这里的 `ninja ... merge_bin` 则是本项目自定义目标。

目前 CMake 允许 `labplus_Ledong_v2` 和 `mpython_v3` 选择 `MICROPY_LANGUAGE=en`；其他板卡只能构建默认中文配置。切换板卡或语言时应使用独立构建目录，避免复用另一组合的 CMake 缓存和 `sdkconfig`。同一仓库的不同板卡构建还会共用 `managed_components/` 和组件锁文件，应串行执行；并行构建可能在链接脚本生成时找不到另一构建刚移除的组件。

## 资源与驱动放置规则

| 内容 | 目录 | 如何进入固件 | 中英文处理 |
| --- | --- | --- | --- |
| 通用 Python 库/驱动 | `port/modules/` | 由 `port/boards/manifest.py` 冻结进应用固件 | 中英文共用；不要在 `port/en/` 复制驱动 |
| 板卡 Python 库/驱动 | `port/boards/<板卡>/modules/` | 由板卡 `manifest.py` 冻结进应用固件 | 按硬件板卡区分，不按界面语言复制 |
| 原生 C 驱动 | `port/drivers/`、`port/builtins/` | 由 CMake 编译进应用固件 | 默认中英文共用；确需语言相关行为时再显式加编译条件 |
| MicroPython 用户 C 模块 | `port/usercmodule/` | 由相应模块的 `micropython.cmake` 加入构建 | 默认中英文共用 |
| 通用文件系统资源 | `port/file_system/common/` | `makeimg.py` 打包进 LittleFS | 两种语言共有的资源放这里 |
| 板卡文件系统资源 | `port/file_system/<板卡>/` | `makeimg.py` 打包进 LittleFS | 中文/默认资源的板卡差异放这里 |
| 英文文件系统覆盖资源 | `port/en/labplus_Ledong_v2/` 或 `port/en/labplus_mpython_pro/` | 仅英文构建时叠加打包进 LittleFS | `mpython_v3` 对应历史目录名 `labplus_mpython_pro`；同路径文件覆盖前面的版本 |

应用代码与资源的组合关系如下：

```text
应用固件（冻结 Python 与编译后的 C）
├─ port/modules/                         通用 Python 库/驱动
├─ port/boards/<板卡>/modules/            板卡 Python 库/驱动
├─ port/drivers/、builtins/、usercmodule/ 原生驱动与 C 模块
└─ 英文开机 Logo：builtins/main.c + 对应板卡的 logo_*_en.h

LittleFS（由 makeimg.py 生成）
├─ port/file_system/common/              通用文件/资源
├─ port/file_system/<板卡>/               板卡默认文件/资源
├─ port/en/<英文资源目录>/                 英文覆盖（仅 MICROPY_LANGUAGE=en）
└─ /lib/firmware_language.py              打包时生成的语言配置
```

`makeimg.py` 先复制 `file_system/common/`，再复制 `file_system/<板卡>/`；英文构建最后复制对应的 `port/en/` 资源目录。`labplus_Ledong_v2` 使用同名目录，`mpython_v3` 使用 `labplus_mpython_pro` 目录。因此英文目录中的同名相对路径文件会覆盖默认版，新文件则会追加。中文固件不读取 `port/en/`。

### K230 AI 驱动的默认语言

`MICROPY_LANGUAGE` 也决定 K230 识别结果标签的默认语言。`makeimg.py` 在临时打包目录最后生成 LittleFS 的 `/lib/firmware_language.py`，其中包含 `LANGUAGE` 和 `IS_ENGLISH`；该文件不是需要手动维护的源文件。公共 `k230_ai` 驱动和两块板各自冻结的 `educore/k230_ai` 驱动读取这一配置，中文固件默认中文、英文固件默认英文。它们仍可调用 `set_voice_language(True/False)` 临时切换识别结果文本，不会改变已编译的 UI、ESP-SR 模型或固件语言。单独复制驱动而没有生成配置文件时，默认回退中文。

### 驱动打印与返回文本语言

`port/modules/mpython_i18n.py` 提供 `localized_text(chinese, english)` 和 `print_i18n(chinese, english, *args, **kwargs)`，按同一个 `firmware_language.IS_ENGLISH` 选择返回或打印的文本；配置文件缺失时默认中文。通用模块和 `labplus_Ledong_v2`、`mpython_v3` 的板级模块都可直接使用：

```python
from mpython_i18n import localized_text, print_i18n

status_text = localized_text("连接成功", "Connected")
print_i18n("连接失败：", "Connection failed:", error)
```

`mpython.RTCdate(0)` 在两种固件语言下都返回 ISO 8601 日期 `YYYY-MM-DD`；`mpython.RTCdate(1)` 按固件语言返回本地化时间文本。若模块通过 `from mpython import *` 使用了定制 `print`，给 `print_i18n` 传入 `printer=print` 可保留原有输出行为。启动握手、MAC 等机器解析串保持固定，不做语言翻译。

### 英文开机 Logo

开机 Logo 与 LittleFS 中的 UI 图片分开处理：英文 Logo 被编译进 C 固件。选择英文构建时，`port/esp32_common.cmake` 定义 `MPYTHON_LANGUAGE_EN`，`port/builtins/main.c` 按板卡分别使用 `logo_labplus_Ledong_v2_en.h` 或 `logo_mpython_v3_en.h`；中文仍调用原有 `lcd_draw_logo()`。修改 `port/en/labplus_Ledong_v2/labplus_Ledong_v2.png` 或 `port/en/labplus_mpython_pro/labplus_mpython_pro.png` 时，也要同步更新对应的 C 数组头文件，普通 LittleFS 打包不会自动生成该头文件。数组格式须为面板传输字节序的 RGB565；若只保留单个颜色通道，白色文字会显示为蓝色。

## 增加英文资源或扩展其他板卡

1. 公共 UI 文件放在 `port/file_system/common/`；板卡默认版本放在 `port/file_system/<板卡>/`。
2. 英文 UI 文件按相同的相对路径放到 `port/en/<英文资源目录>/`。只需覆盖差异文件，不必复制整套默认资源。
3. 语言相关内容尽量限制在 UI、字符串和图片资源；驱动继续放在共享 Python/C 驱动目录或对应板卡模块目录，避免维护中英文两套驱动。
4. 要开放其他板卡的英文固件，需要先补齐该板英文资源、开机 Logo、`sdkconfig.en` 和英文分区表，再修改 `port/CMakeLists.txt` 中的板卡校验，并分别构建、验证该板的中英文镜像。

## 离线语音模型与中英文固件 (ESP-SR)

固件根据 `MICROPY_LANGUAGE` 自动匹配对应的语音神经网络模型：

| 语言 | 唤醒词模型 | 命令词识别模型 | 离线 TTS | 配置文件 |
| :--- | :--- | :--- | :--- | :--- |
| **中文 (`zh`)** | `WakeNet9` (你好小智) | `MultiNet7` (中文量化模型) | 启用 (`xiaoxin.dat` 写入 `voice_data` 分区) | `boards/<板卡>/sdkconfig.board` |
| **英文 (`en`)** | `WakeNet9` (Hi ESP) | `MultiNet7` (英文量化模型) | 禁用（跳过打包 `voice_data`，节省 Flash） | `boards/<板卡>/sdkconfig.en` |

- **C 驱动适配**：`port/usercmodule/audio/src/sr/sr.c` 通过 CMake 宏 `MPYTHON_LANGUAGE_EN` 自动切换模型过滤 (`ESP_MN_ENGLISH` vs `ESP_MN_CHINESE`)，英文固件免除中文 TTS 播报。
- **固件打包**：`port/makeimg.py` 在 `en` 语言模式下跳过写入中文 `voice_data`，仅打包英文模型 `srmodels.bin`。
- **UI 示例**：英文文件系统下的 `ui/voice.py` 使用标准英文短语命令（如 `"turn on the light"`）。
